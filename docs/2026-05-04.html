## Models & Research This week's research batch reveals a field increasingly preoccupied with *failure modes* rather than capability claims — a sign of intellectual maturity, or at least of a community that has absorbed enough benchmark-gaming to start distrusting its own metrics. The most consequential thread running through these papers is a stress-test of whether LLMs can actually *do* what they appear to do on leaderboards, from following procedural instructions to reproducing scientific experiments. Separately, two papers address structural limitations in multimodal and code-reward architectures that practitioners should know about before deploying either at scale.
- **[arXiv] LLMs systematically fail at procedural execution even when final-answer accuracy looks strong** — A controlled diagnostic benchmark tested models on step-wise arithmetic algorithms with two numeric inputs; the study finds that final-answer accuracy is a misleading proxy for whether models faithfully follow the specified procedure, exposing a gap that standard reasoning benchmarks routinely hide. [Link](http://arxiv.org/abs/2605.00817v1) - **[arXiv] Visual attention in autoregressive LVLMs decays as text history grows — a structural flaw, not a tuning problem** — The "Visual Signal Dilution" phenomenon occurs because expanding textual context inflates the attention partition function, crowding out image tokens; the proposed Persistent Visual Memory (PVM) fix is described as lightweight, though independent validation is pending. [Link](http://arxiv.org/abs/2605.00814v1) - **[arXiv] Coding agents largely cannot reproduce computational materials science findings** — Despite strong performance on software engineering benchmarks like SWE-bench, LLM agents stumble on real scientific workflows that demand domain-specific procedural reasoning and result interpretation — a direct warning against extrapolating coding benchmark scores to research automation use cases. [Link](http://arxiv.org/abs/2605.00803v1) - **[arXiv] Themis introduces multilingual, multi-criteria reward models for code, an underserved gap in RLHF tooling** — Existing code reward models optimize almost exclusively for execution correctness, ignoring style, security, and efficiency; Themis targets post-training alignment across multiple criteria and multiple languages simultaneously, which matters for any team deploying code LLMs outside English-centric, single-metric pipelines. [Link](http://arxiv.org/abs/2605.00754v1) - **[arXiv] New NLP framework "Directed Social Regard" moves beyond sentiment polarity to capture targeted advocacy and harm** — Rather than scoring text as positive/neutral/negative, the proposed framework surfaces *who* is directing pro- or anti-social sentiment *at whom*, making it substantially more useful for analyzing influence operations and political rhetoric than off-the-shelf sentiment classifiers. [Link](http://arxiv.org/abs/2605.00776v1)

## Tooling & Agents The agent infrastructure layer is fracturing along a familiar fault line: the promise of autonomous execution versus the reality of compounding failure modes. This week's signal is that serious practitioners are questioning whether current agentic coding frameworks deliver net productivity gains at all, while simultaneously, payment rails and execution platforms are racing to build the plumbing that assumes agents *will* win. The gap between the tooling optimists and the tooling skeptics has rarely been wider.
- **[Hacker News] DeepClaude combines Claude's coding agent loop with DeepSeek V3/R1 reasoning at 1/17th the cost** — The open-source project routes reasoning calls through DeepSeek and execution through Claude's API, exploiting the price differential between frontier models; a pragmatic arbitrage that signals how multi-model orchestration is becoming a cost-optimization primitive rather than a novelty. [Link](https://github.com/aattaran/deepclaude) - **[Lars Faye] "Agentic Coding Is a Trap"** — The argument is specific: agentic coding loops accumulate context debt and error propagation across steps faster than they save keystrokes, leaving developers debugging outputs they didn't write and can't easily audit—a compounding ownership problem, not just a reliability one. [Link](https://larsfaye.com/articles/agentic-coding-is-a-trap) - **[Nate B Jones] Stripe, Visa, Mastercard, Microsoft, and Meta are all building agent-native payment and identity infrastructure simultaneously** — The real shift isn't agents buying coffee; it's that programmable buyer agents invert decades of seller-controlled conversion funnels, and every major payment rail is rushing to become the authentication and authorization layer for non-human principals before a competitor does. [Link](https://natesnewsletter.substack.com/p/agentic-commerce-buyers-power) - **[arXiv] RunAgent proposes constraint-guided execution to enforce determinism in multi-agent plan execution** — Rather than relying on LLM self-consistency, RunAgent inserts stepwise rubrics and hard constraints between natural-language plan steps—an architectural acknowledgment that current models cannot be trusted to maintain workflow state without external guardrails. [Link](http://arxiv.org/abs/2605.00798v1) - **[arXiv] RAG security assessment of a live patient-facing medical chatbot found exploitable backend exposure via the retrieval layer** — The anonymized case study identified privacy and data-source leakage vectors introduced specifically by the RAG architecture, not the LLM itself—a direct warning for teams deploying retrieval-augmented agents in regulated or sensitive domains without security-specific review of the vector store and retrieval pipeline. [Link](http://arxiv.org/abs/2605.00796v1) - **[FT Tech] Enterprise agentic AI adopters report that governance and tool-calling reliability—not raw model capability—are the primary production bottlenecks** — The piece (paywalled) surfaces a consistent theme from early deployers: the hard problems are audit trails, permissioning, and failure recovery, not the underlying model intelligence, which reframes where infrastructure investment actually needs to go.
